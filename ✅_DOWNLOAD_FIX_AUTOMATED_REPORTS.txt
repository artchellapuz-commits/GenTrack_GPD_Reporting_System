========================================
✅ FIXED: Download Button in Automated Reports
========================================

PROBLEM:
When clicking the Download button in Automated Reports execution history,
it showed "Page not found (404)" error because Django couldn't find the file
using the Windows file path with backslashes.

ROOT CAUSE:
- File paths stored in database used Windows backslashes (\)
- Frontend tried to access files via media URL
- Django's static file serving expected forward slashes (/)
- File path wasn't properly normalized

SOLUTION IMPLEMENTED:
=====================

1. BACKEND - views_scheduled.py
   - Added download() action to ReportExecutionViewSet
   - Normalizes file path (converts backslashes to forward slashes)
   - Checks if file exists before serving
   - Returns FileResponse with proper content type
   - Sets Content-Disposition header for download

2. FRONTEND - ScheduledReports.vue
   - Updated downloadFile() function
   - Now uses proper API endpoint: /api/report-executions/{id}/download/
   - Uses axios with responseType: 'blob'
   - Creates blob and triggers download
   - Extracts filename from Content-Disposition header
   - Proper cleanup after download

3. BUTTON UPDATE
   - Changed from: @click="downloadFile(exec.file_path)"
   - Changed to: @click="downloadFile(exec.id)"
   - Now passes execution ID instead of file path

HOW IT WORKS NOW:
=================

1. User clicks "Download" button in execution history
2. Frontend calls: GET /api/report-executions/{id}/download/
3. Backend:
   - Gets execution record by ID
   - Normalizes file path
   - Checks if file exists
   - Serves file with FileResponse
4. Frontend:
   - Receives blob response
   - Creates download link
   - Triggers browser download
   - Cleans up resources

API ENDPOINT:
=============

GET /api/report-executions/{execution_id}/download/

Response:
- Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
- Content-Disposition: attachment; filename="PSR_AUTOMATED_20260213_123456.xlsx"
- Body: Excel file binary data

Error Responses:
- 404: File not found or no file path in execution
- 500: Server error during download
